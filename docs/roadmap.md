# 版本范围与后续计划

首版目标是让自部署统计链路可用并核对指标，不代表最初规划的所有扩展项都已完成。

## 首版范围

- Go 单服务、PostgreSQL 自动迁移、Cookie 管理登录。
- Web/Desktop 应用创建、名称和来源配置、启停。
- 批量事件接收、部分拒绝、事件幂等、7 天离线补报窗口。
- 按应用和匿名标识统计每日活跃与区间活跃。
- 启动、网站会话、页面浏览、新增标识及版本/平台明细。
- Vue 管理台、独立网页 SDK、Python 标准库客户端示例。
- 通过已发布镜像部署的 Compose、可选 Caddy HTTPS、本地构建覆盖文件。
- GitHub Actions 测试及 GHCR 多架构镜像发布流程。
- PostgreSQL 备份、空库恢复工具及文档。

首次镜像发布需要代码仓库与镜像仓库身份；项目文件中的发布流程不会自动创建远程仓库或已经存在的可拉取镜像。

## 已完成（v0.2.0）

- 数据管理：`RETENTION_DAYS` 保留期（默认关闭、启用须至少 7 天，后台分批清理原始事件）、`DELETE /api/apps/{id}` 级联删除应用数据、`POST /api/apps/{id}/rebuild` 范围重建聚合。
- 运行监控：`GET /api/metrics` 采集量/拒收/限流计数、`GET /api/settings` 生效配置查看、`/api/status` 版本字段、采集限流参数显式配置（`RATE_LIMIT_PER_SECOND`、`RATE_LIMIT_BURST`）。
- 统计增强：`custom` 自定义事件（web/desktop 均可，`invalid_event_name` 校验，计入日活与 `daily_metrics.custom_events`）、周留存接口（`GET /api/apps/{id}/retention?weeks=1–12`）、页面路径数字段归一化与前缀白名单（`normalize_numeric_paths`、`allowed_path_prefixes`）。

以上内容已通过本地回归、远程 CI、实际镜像 Compose 验收及服务器升级验证，具体范围与限制见[验证记录](validation.md)。

## 下一阶段：持续运行能力

1. 备份保留策略、调度备份与备份加密；数据保留与删除已覆盖原始事件，备份自身的轮转仍需方案。
2. 数据库容量与延迟指标及可选告警出口；采集请求/拒收/限流计数已由 `/api/metrics` 提供，容量与延迟仍缺。
3. 更新统计时区的受控迁移流程。正式数据产生后不要直接修改统计时区，已有日期列不会自动重算。
4. 根据实际客户端技术栈提供对应官方 SDK，而不是长期只依赖 Python 接入示例。
5. 数据导出接口（按应用导出明细或聚合），先明确范围与隐私边界。

## 按真实需求增加

- 统一登录身份与跨应用去重，先明确身份关联和告知规则。
- 月留存、渠道归因等更多统计维度。
- 多管理员权限、管理员审计和后台密码管理界面。
- 按规模优化数据库分区、聚合索引及采集吞吐；确有必要时再引入队列。

匿名安装/浏览器标识无法准确代表自然人；客户端公开采集标识无法证明事件真实。产品展示和后续分析应始终保留这些口径限制。
