# 版本范围与后续计划

首版目标是让自部署统计链路可用并核对指标，不代表最初规划的所有扩展项都已完成。

## 首版范围

- Go 单服务、PostgreSQL 自动迁移、Cookie 管理登录。
- Web/Desktop 应用创建、名称和来源配置、启停。
- 批量事件接收、部分拒绝、事件幂等、7 天离线补报窗口。
- 按应用和匿名标识统计每日活跃与区间活跃。
- 启动、网站会话、页面浏览、新增标识及版本/平台明细。
- Vue 管理台、独立网页 SDK、Python 标准库客户端示例。
- 通过已发布镜像部署的 Compose、可选 Caddy HTTPS、本地构建覆盖文件。
- GitHub Actions 测试及 GHCR 多架构镜像发布流程。
- PostgreSQL 备份、空库恢复工具及文档。

首次镜像发布需要代码仓库与镜像仓库身份；项目文件中的发布流程不会自动创建远程仓库或已经存在的可拉取镜像。

## 下一阶段：持续运行能力

1. 数据保留、应用数据删除和备份保留策略。删除原始事件前，必须明确事件去重窗口以及版本/页面明细和历史重算依赖。
2. 聚合核对和重建命令；现阶段采集事务直接维护汇总，不提供异步后台重建队列。
3. 将固定的采集限流参数改为显式配置，基于目标流量负载验证后调整。
4. 请求量、拒收量、数据库容量与延迟指标，以及可选告警出口。
5. 更新统计时区的受控迁移流程。正式数据产生后不要直接修改统计时区，已有日期列不会自动重算。
6. 根据实际客户端技术栈提供对应 SDK，而不是长期只依赖 Python 接入示例。

## 按真实需求增加

- 统一登录身份与跨应用去重，先明确身份关联和告知规则。
- 周/月留存、渠道、更多自定义事件。
- 多管理员权限、管理员审计和后台密码管理界面。
- 页面路径白名单/归一化，防止动态路径造成明细规模增长。
- 按规模优化数据库分区、聚合索引及采集吞吐；确有必要时再引入队列。

匿名安装/浏览器标识无法准确代表自然人；客户端公开采集标识无法证明事件真实。产品展示和后续分析应始终保留这些口径限制。
