# 指标口径

所有统计以 `STATISTICS_TIMEZONE` 的自然日归属，默认 `Asia/Shanghai`。客户端上报 UTC 时间，服务端按时区生成事件日。部署后不要随意改统计时区：已有存储日不会自动重算，第一版没有重建工具。

| 字段 | 当前计算方式 |
| --- | --- |
| `active` | 每应用在所选区间出现过任意有效事件的去重 `anonymous_id` 数；每日序列为当天去重数 |
| `starts` | desktop 的有效且未重复 `app_start` 条数 |
| `sessions` | web 的 `session_id` 数，按该 session 最早事件所在日归属；desktop 不计此字段 |
| `page_views` | web 的有效且未重复 `page_view` 条数 |
| `new_visitors` | 该应用 `anonymous_id` 最早事件日在查询范围内的人数 |
| `versions[].active` | 所选区间该版本/platform 组合出现事件的去重匿名 ID 数 |
| `versions[].starts` | 该版本/platform 的启动条数 |
| `pages[].page_views` | 去除 query/fragment 后按路径分组的 page_view 条数 |
| `last_event_at` | 应用已接收事件的最大 occurred_at，迟到的旧事件不会把时间往回推 |

`active` 当前包含启动和页面访问事件。显式 `active` 是补充真实交互的事件，后台周期定时器不能代表用户活跃。区间去重活跃数不是每日活跃数之和。总览按应用分别去重后求和，同一个人使用两个应用会计为两个应用访客，不做跨端身份合并。

新增访客以**已知最早事件日**为准，补报更早事件可能将其归属移动到更早一天。Web session 同样按最早事件日归属；跨午夜保持同一 session 不会在第二天产生新 session 计数，但第二天的活跃/页面访问仍正常计数。服务端没有隐式 30 分钟 session 超时逻辑；随附网页 SDK 会在 30 分钟无事件后自行生成新的 session ID。版本分布各行可能重复同一个访客，因此行数相加可以大于整体活跃数。

Python 示例每进程创建一个 session ID，每个状态目录/应用每进程最多自动记录一次 app_start；`mark_active()` 在真实使用时由调用方触发，同一统计日 5 分钟内合并，跨统计日的首次交互即使相隔不到 5 分钟也记录。没有交互就没有新的 active 心跳。

事件 ID 去重只能避免同一个事件在网络重试时被重复累计。清除客户端状态、更换安装目录、复制状态目录、客户端时钟错误和恶意构造事件都会影响数字。第一版没有设备证明、实名身份、跨端匹配、反作弊评分或真实性认证。请明确向接入方说明采集目的，并避免采集不必要的身份信息。

所有原始事件与聚合持续保留，当前没有定期清理或保留策略配置。直接删事件会影响去重和明细；删聚合会影响总览。跨时区迁移、保留清理、聚合重建和数据库降级均需要后续专门实现，不能仅改配置或删除表完成。
